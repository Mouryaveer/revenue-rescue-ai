# LightGBM Recovery Predictor — Training Guide

## Overview

| Property | Value |
| --- | --- |
| Task | Binary classification (payment recovery probability) |
| Model version | `rr-lightgbm.v1` |
| Framework | LightGBM via scikit-learn Pipeline |
| Training data | Synthetic payment events (~100K samples) |
| Inference | CPU, in-process (no GPU required) |

---

## Quick Start

```bash
# From repository root (with venv activated)
python scripts/train_lightgbm.py
```

Artifacts are saved to `models/artifacts/`:

| File | Description |
| --- | --- |
| `lightgbm_recovery_model.joblib` | Trained model + preprocessor bundle |
| `metadata.json` | Training timestamp, feature order, sklearn version, dataset hash |
| `feature_order.json` | Ordered feature column names |
| `evaluation_report.json` | Metrics on held-out test set |
| `evaluation_report.md` | Human-readable evaluation summary |

## Training Data

- **Location:** `data/training/train.csv`, `data/training/validation.csv`, `data/training/test.csv`
- **Feature spec:** `data/preprocessed/feature_spec.json`
- **Nature:** Synthetic — generated by the simulator for development purposes
- **Splits:** Pre-split with no data leakage between train/validation/test

> [!WARNING]
> Metrics computed on synthetic data. Real-world performance will differ.

## Features

### Categorical (OneHotEncoded)

| Feature | Examples |
| --- | --- |
| `event_type` | FAILED_PAYMENT, CHECKOUT_ABANDONMENT, FAILED_SUBSCRIPTION |
| `failure_reason` | INSUFFICIENT_FUNDS, GATEWAY_TEMPORARY, BANK_DECLINE, etc. |
| `payment_method` | card, upi, netbanking, wallet |
| `device_type` | web, mobile_app, mobile_web |
| `country` | IN, US, etc. |

### Numeric (StandardScaled + Imputed)

| Feature | Description |
| --- | --- |
| `amount_paise` | Transaction amount in paise (1/100 INR) |
| `retry_count` | Number of previous retry attempts |
| `event_hour_utc` | Hour of the event (0-23) |
| `event_dayofweek_utc` | Day of week (0=Monday, 6=Sunday) |
| `event_month_utc` | Month (1-12) |

---

## Leakage Prevention

- **No post-event features** — recovery status, outcome codes, and verification results are excluded
- **No future customer-history features** — only event-level data available at decision time
- **Preprocessing fitted on training data only** — OneHotEncoder, StandardScaler, SimpleImputer
- **Validation set** — used for hyperparameter tuning and calibration
- **Test set** — evaluated exactly once for final metrics

---

## Model Architecture

```text
Input Features
    │
    ├─► Categorical ──► OneHotEncoder (handle_unknown='ignore')
    │
    ├─► Numeric ──► SimpleImputer (median) ──► StandardScaler
    │
    └─► ColumnTransformer
            │
            ▼
        LightGBMClassifier
            │
            ▼
        CalibratedClassifierCV (isotonic, on validation set)
```

**LightGBM parameters:**
- `num_leaves=31`
- `learning_rate=0.1`
- `n_estimators=500`
- `early_stopping_rounds=50`
- `objective=binary`

| Metric | Value |
| --- | --- |
| ROC-AUC | ~0.6649 |
| Average Precision | ~0.7795 |
| Brier Score | ~0.2258 |

Precision, recall, F1, and calibration details are in `models/artifacts/evaluation_report.json`.

> [!IMPORTANT]
> These metrics are measured on synthetic data. They reflect model behavior on the training distribution, not real-world payment failure patterns.

## Expected Value Calculation

```
EV (paise) = (recovery_probability × amount_paise) - intervention_cost_paise
```

| Parameter | Default | Notes |
| --- | --- | --- |
| `recovery_probability` | Model output | Bounded [0.0, 1.0] |
| `amount_paise` | From payment event | Transaction amount |
| `intervention_cost_paise` | 500 (₹5.00) | **Configurable assumption** — not measured |

- All values in **paise** for unit consistency
- Currency assumed **INR** — no automatic conversion
- `expected_value_inr` is derived as `expected_value_paise / 100`

## Retry Timing

> [!NOTE]
> Retry delay recommendations are **rule-based, not ML-predicted**. They use a lookup table based on `failure_reason` and `retry_count`.

| Failure Reason | Retry 0 | Retry 1+ |
| --- | --- | --- |
| GATEWAY_TEMPORARY | 2h | 4h |
| INSUFFICIENT_FUNDS | 24h | 48h |
| BANK_DECLINE | 48h | 72h |
| EXPIRED_METHOD | 0h (no retry) | 0h |
| Other | 24h | 48h |

All outputs are labelled as `rule_based_retry_delay_hours`.

## Fallback Behavior

| Condition | Behavior |
| --- | --- |
| Model artifact missing | Falls back to `RecoveryScoringService` heuristic |
| Model load error (e.g., sklearn version mismatch) | Falls back to heuristic, logs error |
| Model version | Becomes `not_trained_fallback` or `load_error_fallback` |
| Predictions | Remain bounded [0.0, 1.0] |
| Downstream system | Works identically in fallback mode |

## Retraining

1. **Regenerate training data** (if needed):
   ```bash
   python -m simulator.scripts.generate_training_data
   ```

2. **Run training:**
   ```bash
   python scripts/train_lightgbm.py
   ```

3. **Review metrics:**
   ```bash
   cat models/artifacts/evaluation_report.md
   ```

4. **Commit** new artifacts if metrics are acceptable
